# 馬卡龍 3D 建模與驗收標準

狀態：Canonical

最後核對：2026-08-16

已通過基準：窗邊手記（Emu Rabbit Github io），模型 commit `fe49b38`

## 文件責任

本文件持有十顆馬卡龍的 3D 建模、共用幾何、對圖與交付驗收規則。口味、色彩、內餡語意、裝飾主題與 2D 美術規格仍由 [`macaron-visual-system.md`](macaron-visual-system.md) 持有；本文件不重新定義個別設計。

這裡的標準不是「下一顆可以參考的風格建議」，而是必須全部通過的基本門檻。模型能開啟、GLB 能匯入或網站能顯示，只能證明技術格式有效，不能取代嚴格的視覺驗收。

## 真相來源與優先順序

遇到資料不一致時，依下列順序判斷：

1. 使用者當次明確指示與已確認修正。
2. `macaron-visual-system.md` 與該顆正式 2D current asset。
3. 已由使用者接受的正式 `.blend` 與網站實際載入的 `.glb`。
4. 寫實照片或多視角參考，只用來理解烘焙結構、材質與合理厚度。
5. 生成腳本、暫存輸出與舊截圖；它們是實作來源或歷史證據，不可推翻較高層級的已接受結果。

### 已知重建風險

截至 2026-08-16，正式 `.blend` 裡已調整完成的拱窗與窗板 transform，和直接重跑 `create_window_notes_macaron.py` 得到的程序版本不同。這表示目前腳本不能單獨完整重建已接受模型。

- 不得因腳本成功產生 `.blend/.glb`，就直接覆寫正式模型。
- 若只修改共用外殼、裙邊或單一裝飾，應在正式 `.blend` 的副本中精確替換目標部件，保留其他已接受 transform。
- 若要把生成腳本升格為完整 source of truth，必須先證明它重建後的正面、三分之四、側面與背面構圖都和正式模型一致，再淘汰這項警告。
- `.tmp/` 內的檔案與一次性合併腳本不是 repository 契約，不可把它們當成未來 Agent 一定存在的工具。

## 共用圓蓋基準

### 不變規則

窗邊手記目前通過的上、下圓蓋，是十顆馬卡龍可直接複用的共用幾何基準。下一顆預設應複製這兩個 shell mesh，只替換材質、貼圖與顏色；不得每顆重新用 UV sphere、圓柱、torus 或新的自由曲面從零猜輪廓。

允許改變：

- 上、下蓋各自的色彩、杏仁粉細紋、roughness 與極小幅度色差。
- `macaron-visual-system.md` 已明定的同盒輪廓變體；若需改成「稍高」或「稍寬」，必須從共用基準做可比較的比例變形，並另外取得視覺接受。

不得改變：

- 寬而平滑的圓頂主曲面。
- 外緣接近末端才快速向下／向內收的急轉折。
- 上下蓋的基本直徑、邊緣厚度語言與同盒一致性。
- 轉動時連續、無破面、無明顯分段的外輪廓。

「更平滑」只代表增加曲面連續性、降低不必要的凹凸與 faceting；不代表把外緣急轉折磨成球體，也不代表移除手作杏仁殼的細微表面變化。

### 複用方式

建立下一顆模型時：

1. 複製正式 `window-notes-macaron.blend` 到新的工作檔，不直接修改基準檔。
2. 保留 `Upper night-violet shell` 與 `Lower night-violet shell` 的 mesh 幾何；可以依新作品重新命名物件與材質。
3. 為新作品建立獨立材質／貼圖 datablock，避免修改共用材質後連帶改壞基準模型。
4. 先完成共用圓蓋的材質替換，再依 2D 圖建立該顆專屬裙邊、餡料與裝飾。
5. 若改動 shell 幾何，必須提供與基準疊合或同視角並排的證據，指出改動理由；沒有明確設計需求時應回復共用幾何。

未來若建立正式共用 shell library，必須從已接受 `.blend` 抽取，不可從尚未完全重現正式構圖的暫存程序檔反向建立。

## 已通過模型的視覺解剖

窗邊手記是目前第一個完整通過的 3D 基準，需保留以下判斷：

| 部位 | 通過特徵 | 不通過例子 |
| --- | --- | --- |
| 上、下圓蓋 | 大面平滑、杏仁粉感克制、外緣保留快速收折 | 球體感、厚圓角、明顯多邊形、噪點像毛氈或石頭 |
| 裙邊（pied） | 是連續的鬆脆烘焙帶；有皺褶、凹陷與可讀的深色氣孔 | 光滑 torus、散落碎塊、尖刺、破洞穿透、只畫黑點假裝氣孔 |
| 內餡 | 兩層厚實暖白奶霜，中間一條較窄的杏桃蜂蜜果膠；順序、比例與 2D 一致 | 合併成單一白柱、果膠比奶霜厚、層序錯誤、餡料凸出成塑膠輪胎 |
| 拱窗 | 紫色拱框、暖橘窗光、只露白兔耳；右側焦糖窗板微開且有合理厚度 | 完整兔子、窗板攤平、窗框歪斜、薄片穿插或只在正面成立 |
| 星環 | 五顆星依綠、粉、綠、粉、綠排列，連續半月枝線包住窗戶下方 | 星數／色序錯、淺笑線與窗戶分離、線段斷裂或穿過窗板 |
| 交錯圓球 | 圓潤飽滿的小球沿主枝與兩端上升枝規則交錯，每顆由短枝接回主線 | 把「枝葉」做成真的葉片、隨機散珠、懸浮球、隨便加圓圈或左右無節奏 |

窗邊手記目前正式模型的交錯圓球共有 16 顆，這是該模型的已接受 snapshot，不是其他九顆都必須複製的裝飾數量。可重用的是「先讀懂 2D 節奏，再以確定性的曲線與連接關係建模」這項方法。

## 嚴格對圖契約

### 建模前必做拆解

任何新馬卡龍開始建模前，先從正式 2D current asset 建立一份元件對照；至少記錄：

| 欄位 | 必須回答的問題 |
| --- | --- |
| 圓蓋 | 上下顏色是否相同？只需換材質，還是真的有已核准輪廓變體？ |
| 裙邊 | 顏色、露出高度、粗糙度與氣孔密度如何？ |
| 內餡 | 有幾層？由上到下的順序、相對厚度、顏色與材質是什麼？ |
| 果膠／醬 | 位於哪兩層之間？是連續帶、局部結果或透明滴狀？ |
| 主裝飾 | 唯一記憶點是什麼？數量、方向、位置、大小與遮擋關係為何？ |
| 陪襯 | 哪些是糖珠、糖線、碎粒或節點？節奏是對稱、交錯、分岔還是收束？ |
| 立體理由 | 每個 2D 元素在側面應有何厚度、支撐與接觸點？ |

沒有完成這份拆解前，不應靠「先做一版看看」任意增加裝飾。隨機種子只可用於微小表面紋理、烘焙孔洞與手作誤差，不可決定星星、糖珠、節點、分枝或主裝飾的構圖。

### 餡料

- 層數、由上到下的順序、厚度關係與色彩必須和 2D 圖逐項對齊。
- 奶霜、果膠、醬心與薄脆是不同材料時，必須是可辨識的不同 3D 部件，不能只靠同一 mesh 上換色。
- 正面輪廓要忠於 2D，但側面與背面也必須補成合理連續結構；不得只做鏡頭前的一段立面。
- 手作不等於失控：可有小幅起伏，但不能改變設計的層數、比例或主視覺節奏。
- 任何「看起來更豐富」但 2D 沒有的額外奶霜、果醬滴、糖珠或碎粒，預設不接受。

### 裝飾

- 主裝飾的種類、數量、色序、方向、相對位置與大小都屬於設計，不是自由發揮區。
- 形容詞與造型名詞必須分開理解。「像枝葉交錯」可以描述排列節奏，不等於要加入葉形 mesh；應回看 2D 的實際輪廓再建模。
- 每個部件要有合理厚度、背面與接觸方式；旋轉後不得懸浮、裂開、互相穿透或變成紙片。
- 曲線裝飾要用足夠採樣形成連續弧線；控制點不能在端點回折，不能用多段短管假裝一條完整枝線。
- 重複元素應由明確序列控制。需要交錯時，依曲線切線建立左右法線與固定順序，不用隨機位置碰碰運氣。
- 2D 正面是構圖基準；三分之四、側面與背面用來驗證物理合理性，不可藉 3D 延伸改掉正面設計。

## 常見問題與修正方向

| 問題 | 常見誤判 | 正確處理 |
| --- | --- | --- |
| 圓蓋不夠滑順 | 直接增加 bevel，把整個外緣磨圓 | 增加曲面採樣並減少高頻 displacement，同時鎖住末端急轉折 |
| 裙邊不像真實馬卡龍 | 用規則 torus 或散落 crumbs 代表鬆脆 | 先做連續 pied 主體，再加入折皺、局部凹陷與有深度的氣孔 |
| 裙邊破碎 | 以過深位移或獨立碎塊切壞外輪廓 | 降低位移幅度，氣孔做淺凹腔；旋轉確認沒有穿洞與漂浮 |
| 裝飾「有元素但不像圖」 | 只確認有星星／珠子，不確認數量、順序、路徑與比例 | 以 2D landmarks 逐項比對並鎖定相對位置 |
| 把比喻做成字面造型 | 把枝葉交錯理解成真的葉片 | 先描出 2D 實際 silhouette；窗邊手記應是交錯圓球，不是葉子 |
| 星環像散珠 | 圓球直接放在殼面，沒有生長方向 | 每顆球用短枝接回連續主線，並依切線法線交替左右 |
| 星環或糖線斷裂 | 稀疏折線、短管拼接或端點回折 | 使用連續、密集取樣的平滑曲線，側面檢查接點 |
| 正面正確、轉動就失效 | 使用薄平面、貼圖或只完成鏡頭側 | 所有主要造型補足厚度、背面、支撐與遮擋關係 |
| 程序重建造成回歸 | 把「腳本跑完」當成「模型相同」 | 將生成結果與正式 `.blend/.glb` 多角度比對，未達 parity 不得覆寫 |
| 為了手作感加入太多隨機 | 隨機改變主輪廓與裝飾構圖 | 隨機只服務微表面；設計幾何使用確定性參數 |

## 驗收閘門

以下五項必須全部通過；任何一項失敗都不能標記完成。

### 1. 2D 對齊

- 以該顆正式 current asset 為同畫面對照。
- 圓蓋色彩、餡料層數／順序／比例、主裝飾與陪襯的數量、色序、方向、位置都逐項相符。
- 沒有自行增加、刪除或把比喻字面化的元素。

### 2. 共用外殼一致性

- 未經核准的情況下，上下圓蓋沿用已通過 shell 幾何。
- 大面平滑但外緣急轉折仍在。
- 表面材質與新口味相符，且沒有把同盒畫風改成塑膠、石材、毛氈或攝影掃描質感。

### 3. 立體完整性

- 檢查正式預設三分之四視角、正面、左右側、背面與略高視角。
- 無懸浮、裂縫、破面、穿插、反向法線、意外洞口或視角限定的紙片造型。
- 裙邊氣孔、餡料與主裝飾具有合理實體厚度。

### 4. 正式網站驗收

- 使用網站實際載入的 `.glb`，不可只看 Blender viewport。
- 重設視角後的第一畫面必須清楚讀到 2D 的唯一記憶點與餡料結構。
- 實際拖曳旋轉與縮放，確認構圖連續、陰影正常、模型未被裁切。
- 檢查桌機與手機可用尺寸、明亮／暗色主題、載入失敗狀態與 console error。

### 5. 交付一致性

- `.blend`、`.glb`、程序來源與文件中的 current-state 說明不能互相冒充；已知不能完全重建時要明確保留警告。
- GLB 重新匯入後，主要部件數量、名稱或可搜尋的 semantic prefix 符合預期。
- 執行 `npm run build`，並以 `git diff --check` 檢查文字變更。
- 不提交 Blender 自動產生的 `.blend1`，不把 `.tmp/` 暫存檔當成正式資產。

## 下一顆馬卡龍的建模順序

1. 讀取 `macaron-visual-system.md`、本文件與該顆正式 2D current asset。
2. 完成元件對照表，先確認餡料層序與唯一主裝飾。
3. 從正式通過模型的上下 shell 建立工作副本，只換新材質／貼圖。
4. 先用大形完成裙邊與所有餡料，從預設展示視角比對 2D silhouette。
5. 再建立主裝飾，最後才加入 2D 確實存在的陪襯。
6. 每個階段都做一次正面與側面檢查；不要等所有細節完成後才發現厚度、支撐或構圖錯誤。
7. 匯出候選 GLB，在正式網站 viewer 進行多角度驗收。
8. 只有在五個驗收閘門都通過並取得使用者視覺接受後，才把該模型列為下一個可複用基準。
