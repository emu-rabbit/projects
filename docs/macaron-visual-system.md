# 馬卡龍收藏視覺系統

狀態：Canonical

最後核對：2026-08-19

資產目錄：`.agents/designs/`

## 核心設計語法

每顆馬卡龍都使用同一套可讀的甜點結構：

- **外殼＝品牌與第一印象。** 成熟專案沿用品牌色；沒有成熟品牌時，以問題領域選色。
- **內餡＝產品真正做的事。** 分層、比例、節點、果膠與擠花方式要能對應資料流或主要行為。
- **表面裝飾＝唯一記憶點。** 每顆選一個最值得記住的符號；陪襯只能協助構圖，不能再搶一個主題。
- **分級＝細節密度，不改畫風。** Signature、Experiment、Classic 的差異來自裝飾層級；線條、材質、視角與手作感保持一致。

## 全盒共同規格

### 畫風與材質

- 暖棕色鉛筆線，不使用純黑硬輪廓。
- 粉彩、水彩或廣告顏料般略不均勻的著色。
- 殼面保留細緻杏仁粉感，裙邊鬆脆，餡料厚實且略有手工誤差。
- 使用柔和、均勻的棚拍式光線；不要把某一顆改成攝影寫實、向量圖、珠寶渲染或厚重油畫。
- 馬卡龍是單一完整主體，採相近的三分之四正面視角、比例與留白；不要加入桌面、場景、餐具或獨立道具。
- 正式 2D 資產使用透明背景；不得把棋盤格烘焙進圖片。

### 一致而不複製

- 可使用三種略有差異的基礎輪廓：圓潤、稍高、稍寬；同一分級不必全部同形。
- 每顆最多一個主裝飾群。主裝飾之外，只能使用一段糖珠弧線、一小段擠花邊或少量天然碎粒作為陪襯。
- 全盒的裝飾語彙固定為可食用結構：糖片、糖珠、果膠、奶霜、薄脆、糖線與少量金砂。
- 不直接貼大型框架 Logo；只有當字元或數字本身就是產品行為時，才可出現單一短文字，例如 `あ` 或 `75%`。

### 分級密度

| 分級 | 視覺密度 | 構圖規則 |
| --- | --- | --- |
| Signature | 精緻、特別、克制 | 一個完成度高的主裝飾群，加一段有節奏的糖珠／擠花陪襯；內餡也必須說故事。 |
| Experiment | 清楚、有機關感 | 一個技術機制成為主角，可用少量節點或材料呈現狀態變化。 |
| Classic | 輕巧、直接 | 一個角色、字、比例或練習提示；不使用華麗花材、蝴蝶結與珠寶裝飾。 |

## 多視角 2D 轉譯契約

畫廊資訊架構、圖片處理、全螢幕互動與交付閘門由 [`macaron-gallery-acceptance.md`](macaron-gallery-acceptance.md) 持有。預設三分之四視角是每顆馬卡龍的設計真相；頂面與側面只補充不同角度能合理看見的結構，不重新設計甜點。

- 外殼、裙邊、各層內餡、果膠與頂部糖飾的顏色、層序、比例、數量與色序必須和正式 current asset 一致。
- 多視角圖保持暖棕線條、手繪著色與克制的杏仁粉質感，不改成攝影、塑膠 3D render 或制式產品圖。
- 被角度遮住的裝飾應依物理關係自然隱藏，不能為了「元素齊全」把正面裝飾複製到側面。
- 三視圖的預設視角是最大主圖；頂面與正常平放的水平側面以較小尺寸上下排列。
- 衍生視角可以補足合理可見的側面結構，但不得改變本文件指定的口味、主色、內餡邏輯與唯一記憶點。

## 十顆馬卡龍規格

### Signature／主要焦點專案

#### Frozen Rabbit Workshop — 薄荷青檸馬卡龍｜薄荷・青檸・白巧克力

- 薄荷綠外殼、暖白厚奶霜與一條青檸果膠。
- 奶霜分成整齊段落，表達購買、製作、採集與庫存被整理完成。
- 主裝飾是勾選糖牌；青檸糖珠與短擠花邊形成陪襯節奏。
- 氣質是清楚、實用、準備充分；它是全盒細節密度與手作華麗度的基準。

#### Frozen Rabbit Tome — 森林綠柚馬卡龍｜深焙抹茶・柚子金砂

- 深森林綠上殼、較淺 Frozen Rabbit 綠下殼，與 Workshop 一眼可見為姊妹款。
- 暖象牙奶霜形成四至五片寬而清楚的書頁層，中間保留一枚柚子果膠結果。
- 主裝飾是一條有約五個節點、分岔後收束的奶油糖線；末端只留一組小葉片與礦石糖。
- 金色只作微量砂糖點綴，不使用珠寶、金屬藤蔓或大面積金砂。
- 氣質比 Workshop 深、靜、需要慢慢閱讀，但複雜度與畫風仍屬同一盒。

#### Boundary Notes — 酒紅邊界馬卡龍｜黑醋栗・玫瑰伯爵

- 柔和酒紅外殼、淡玫瑰與暖象牙奶霜；中央是一條筆直、清楚的黑醋栗果膠界線。
- 主裝飾是一片折起的象牙色信箋糖片，使用小型兔耳蠟封；短奶油擠花與玫瑰糖珠弧線作陪襯。
- 特別感來自克制、對稱與材質層次，不使用鎖、鑰匙孔、鎖鏈、皮革、項圈或鞭子。
- 氣質成熟、安靜、私密且尊重，不落入侵略性的黑紅 BDSM 套路。

#### Emu Rabbit Github io — 紫夜兔耳馬卡龍｜暮色杏桃・蜂蜜玫瑰

- 夜色紫外殼、暖奶油白內餡與一條窄而透亮的杏桃蜂蜜果醬，像室內燈光。
- 主裝飾是一扇微開的拱窗糖片；窗內只露出白色垂耳兔的兩隻耳朵。
- 三至四顆玫瑰粉、苔綠糖葉或星形糖，加一段短奶油糖線形成半月陪襯。
- 不使用 GitHub Logo，也不放完整兔子角色；這顆講的是創作者本人與可以靠近的生活空間。

### Experiment／技術實驗專區

#### LinkArray — 黑白鏈結馬卡龍｜黑白芝麻・鹽焦糖

- 象牙白芝麻上殼、炭灰黑芝麻下殼。
- 黑白奶霜節點交錯排列，以單一焦糖鏈環表達 doubly linked list。
- 節點由稍亂到整齊，表達 `refactor`；互動可在未來沿用這個重排概念。

#### Vue Router Rule — 綠葡萄荔枝馬卡龍｜青葡萄・荔枝・紫羅蘭

- Vue 綠外殼、荔枝白與淡紫羅蘭內餡。
- 分岔、判斷、重新匯合的糖線路徑是主角；節點可分別表示允許、拒絕與重新導向。
- 獨角獸只以一根小珠光糖角或極少彩色碎屑提示，不貼大型 Vue Logo。

#### Dandelifeon — 蒲公英魔力馬卡龍｜蒲公英蜜・青蘋果

- 蒲公英黃上殼、植物綠下殼、蜂蜜奶霜與青蘋果果膠。
- 蒲公英與藍綠 mana 糖珠形成單一主裝飾群；少量不同形狀糖粒提示三種搜尋演算法。
- 若加入棋盤，只能作低對比薄糖片，不能與蒲公英同時成為第二主角。

### Classic／早期小作品

#### nAnB — 小倉鼠藍莓馬卡龍｜藍莓優格・葵花子

- 聊天室靛藍上殼、深灰下殼、白色優格奶霜。
- 夢夢黃金鼠臉是唯一主裝飾；綠黃糖珠提示 A／B，葵花子碎只作少量陪襯。
- 保留有點嘴壞又可愛的聊天室機器人個性，但不增加複雜機關或把它做成華麗角色甜點。

#### 75 Alchohol — 白葡萄蘇打馬卡龍｜白葡萄・檸檬蘇打

- 白色上殼、淡水藍下殼；透明白葡萄果膠與淡黃檸檬奶霜形成兩種可見比例。
- `75%` 糖牌與透明糖滴構成單一計算提示；糖牌的視覺量感約為 Hiragana `あ` 裝飾的 50–60%，確保縮成小圖時仍可辨認，但不可搶過主體；刻度不固定成來源濃度無法支持的比例。
- 不使用醫療紅十字或實驗室器材堆疊。

#### 50 Hiragana Test — 櫻花紅豆馬卡龍｜櫻花牛奶・紅豆

- 淡櫻花粉上殼、暖米白下殼、單純的牛奶奶霜與一小點紅豆餡。
- 上殼只保留一個暖棕糖霜 `あ`；最多加一片低對比四格練習紙糖片。
- 禁用蝴蝶結、櫻花、花瓣、金飾、多張紙片與散落裝飾；這顆必須是全盒最輕巧的之一。

## 視覺驗收清單

- 縮小同時觀看十顆時，沒有一顆像攝影、向量或珠寶系列而脫離群體。
- 四顆 Signature 的細節更完整，但輪廓、線條與材質沒有比其他作品換一套作者語言。
- 每顆在不看名稱時仍能由唯一主裝飾或內餡結構被辨識。
- Tome、Boundary、Emu 的華麗度接近 Workshop：有節奏、有焦點、留有空白。
- Hiragana 的視覺元素不超過 `あ`、一片練習紙與紅豆內餡，沒有花與蝴蝶結。
- 所有 current asset 都是 1254 × 1254 透明 PNG，四角 alpha 為 0，主體未裁切。
- 十張 current asset 的 alpha bbox 最長邊都是 1050 px（重採樣誤差最多 1 px），且 bbox 中心與畫布中心偏差不超過 1 px。
- 任何後續多視角圖都能逐項對回預設 current asset 的殼、餡、果膠與頂部裝飾。

## 前端文字與視覺交付契約

### 字型 subset

- 網站正文使用 `assets/fonts/emu-portfolio-round-subset.woff2`；它是由 jf open 粉圓 2.1 產生的專案字元 subset，不是可以在文案變更後繼續沿用的完整字型。
- 只要 `index.html`、`src/**/*.vue` 或 `src/data/**/*.ts` 的使用者可見文字有增減，交付前必須用官方 jf open 粉圓 2.1 TTF 重跑 `scripts/subset_huninn.py`，並將更新後的 WOFF2 與文案一起納入變更。
- 標準呼叫方式是 `python scripts/subset_huninn.py <jf-openhuninn-2.1.ttf>`。來源 TTF 的本機路徑不寫進 repository；字型授權資訊由 `assets/fonts/OFL.txt` 持有。
- 目前腳本會收集 `index.html`、`src/**/*.vue` 與 `src/data/**/*.ts`。如果日後可見文字移到其他位置，要同步擴充 `TEXT_SOURCES`，不能以系統 fallback 字型掩蓋缺字。

### 交付前視覺驗收

- 任何使用者可見的 UI、文字、圖像或 responsive 變更，交付前必須開啟實際網頁進行視覺檢查；只有 build、typecheck 或閱讀 CSS 不算完成視覺驗收。
- 至少檢查桌機、平板、手機三種版面，以及明亮與暗色主題。必須確認無橫向溢出、文字裁切、缺字／錯誤 fallback、對比不足、卡片高度或 CTA 錯位與明顯 CLS。
- 視覺判斷必須回到本文件的美術要求：馬卡龍是主角，介面克制、暖和、手作、一致且易讀；要主動移除會增加認知負荷、暗示未開放互動或與主視覺爭奪注意力的元素。
